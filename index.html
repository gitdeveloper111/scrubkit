The workflow

The point isn't just to delete sensitive strings — it's to keep the text usable, so the model still gives you a real answer and you can read that answer with the real values in it.

1

Paste. Your log, ticket, config or trace goes into the left box. It never leaves the tab.

2

Scrub. Each sensitive value becomes a stable placeholder like [EMAIL_1]. The same value always gets the same placeholder, so relationships in the text survive.

3

Ask. Paste the safe version into any AI chat. It still reads as coherent text, so the answer is still useful.

4

Restore. Paste the reply into tab 2 and the placeholders turn back into your real values.

Be realistic about what this is. ScrubKit is pattern-based. It reliably catches structured things — keys, tokens, cards, IBANs, emails, IPs. It does not understand prose, so it will not catch a person's name, a street address written out longhand, or a secret that looks like ordinary English. Read the output before you send it. Treat this as a strong safety net, not a guarantee.

What it catches

Every detector is validated, not just regex-matched — card numbers are Luhn-checked, IBANs are mod-97 checked, SSNs are structurally validated, and generic secret = "..." matches are entropy-gated. That's what keeps version numbers, dates and order IDs out of your results.

Questions

Is my text really not uploaded?

Correct. The detection engine is plain JavaScript running in your tab. There is no backend, no analytics call carrying your text, and no storage. You can verify it: open your browser's Network tab, scrub something, and watch nothing happen. You can also save this page and run it with your Wi-Fi off.

Why placeholders instead of just deleting the values?

Because deleted text destroys the question. If three log lines mention the same host and you blank all three, the model can't tell they were the same host. Stable placeholders keep the structure — and they let you turn the answer back into something you can act on.

Will it catch names and addresses?

No, and any tool that claims to catch them from regex alone is overselling. Names and free-form addresses need language models to spot reliably. ScrubKit deliberately sticks to things it can validate, so you get very few false positives — then you do a five-second read of the output.
